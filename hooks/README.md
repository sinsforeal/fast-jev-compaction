# fast-jev-compaction Claude Code mod

This plugin uses Claude Code function hooks to replace a compaction with the
original messages, minus the tool calls and tool results Jev judged no longer
needed. `hooks/fast-jev.ts` is a thin adapter: it reads the plugin options,
finds the TypeSafe key, hands `session.compact` transcripts to the
`fast-jev-compaction` library in `src/` (the plugin folder is the repository
root, so the hook imports it directly) and maps the result back onto session
messages. Recognized injected text and old long replies are candidates too. Jev is sent the whole
conversation as `state` (tool outputs replaced by a one-line note) and, for
every tool call outside the pinned first and newest messages, two questions:
whether the call should stay and whether its full output should stay. An
item is kept when Jev's probability reaches `keepThreshold`; a dropped result
is truncated to its first `truncateHeadChars` characters plus a one-line note,
and a dropped call disappears with its result, leaving a short evidence marker.

The state is fitted into `maxStateTokens` in stages: tool inputs are
truncated, then long texts are abridged (oldest first, pinned messages last),
then old messages collapse to a `[… N chars omitted …]` note, then old tool
calls shrink to one line each, then old call-less messages are left out and
runs of old call-only messages fold together. Questions are split into as many requests as
needed so each request (state plus questions) stays under `maxRequestTokens`;
the full state is resent with every request. Token counts are estimated
without a tokenizer, calibrated to land a little above what Jev reports.

The mod is an early-access Claude Code function-hook module. The checked-in
type reference was generated by Claude Code **2.1.274**; the additional
read-only `session.append` and `session.messages({agentId, as: 'api'})` contracts
are verified on **2.1.299**. Older
hosts may reject that event during module scanning, so keep 0.3.0 for rollback.
Enable the function
hooks surface before installing or loading it:

```sh
export CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1
export TYPESAFE_API_KEY="<your TypeSafe key>"

claude plugin marketplace add 'sinsforeal/fast-jev-compaction#fidelity/jev-041-20261014'
claude plugin install fast-jev-compaction@fast-jev-compaction
```

For local development:

```sh
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir .
```

## Configuration

The plugin declares these `userConfig` values in
`.claude-plugin/plugin.json`:

| Option | Default |
| --- | ---: |
| `keepThreshold` | `0.5` |
| `preserveRecentMessages` | `6` |
| `compactAtPercent` | `60` |
| `minReductionRatio` | `0.25` |
| `maxStateTokens` | `25000` |
| `maxRequestTokens` | `30000` |
| `truncateHeadChars` | `300` |
| `model` | `jev-latest` |
| `injectedMinChars` | `1000` |
| `replyMinChars` | `2000` |
| `maxPostCompactTokens` | `0` |
| `logDecisions` | `false` |
| `compactAtTokens` | `128000` |
| `targetVisibleTokens` | `64000` |
| `handoffAt` | `250000` |
| `handoffForceAt` | `300000` |
| `handoffDir` | unset |
| `handoffSkillPath` | `docs/HANDOFF_SKILL.md` |

The TypeSafe key can be supplied as the sensitive `apiKey` plugin option or
through `TYPESAFE_API_KEY`. The environment variable is the recommended
development setup.

Every option except `apiKey`, `compactAtPercent`, `compactAtTokens`,
`targetVisibleTokens`, `handoffAt`, `handoffForceAt`, `handoffDir`,
`handoffSkillPath`, `minReductionRatio`, `maxPostCompactTokens`, `logDecisions`
and `model` is passed to the library; see the root README for what they do. The
`session.compact` hook runs the Jev requests concurrently. Engine request
failures, invalid results and local preparation failures log the reason and use
deterministic transcript recovery. Text and calls stay; eligible older results
are truncated with the existing evidence notes. The
[root fidelity rules](../README.md#fidelity-rules) describe the policy.
A `minReductionRatio` miss returns `{ skip }` and writes a marker file; the
built-in summary is never requested. `targetVisibleTokens` re-decides the cut
from the cached probabilities until the visible estimate is at or under it.
`maxPostCompactTokens` only warns. The outcome includes the estimated visible
post-cut size and the threshold used. Detailed kept/dropped probabilities, skip
counts and text scores are logged only with `logDecisions: true`; arbitrary
output and transport error bodies are omitted from diagnostics. The
`turn.complete` hook requests compaction when `context.tokens` reaches
`compactAtTokens` (or `context.percent` reaches `compactAtPercent` when the token
value is unset), with an in-flight guard checked again after the usage read and a
32000-token hysteresis after a prune or skip. It then runs the handoff step:
orders at `handoffAt` and `handoffForceAt`, the clear and the resume once
`<handoffDir>/<sessionId>/latest.md` is complete (see `handoff.ts`). Subagent
completions cannot request a main-session cut. `precompute` is vetoed before
network or UI work; it prepares a speculative result that the engine may never
apply.

The first actual cut after start/reload uses Jev's handleless rebuild. Observers
pin accepted mid-turn text/context and rendered deliveries; all append doors
supply UUID chronology. Canonical queued deliveries replace provisional prompt
records instead of duplicating them. The bounded API-tail view recovers known
historical hidden text and selects the compacting child by `agentId`; it never
replaces the older projected prefix. Child attachments rendered as text are
passed verbatim and unscored. Opaque blocks are logged, text is retained, and
missing anchors resolve by occurrence and transcript order. New arrivals during scoring are restored before
returning history. No persistent shared store is written. Jev replacements rebuild
pin provenance as one separate metadata row for the next reload/resume; original
instruction rows remain verbatim. Replacements rebuild
every row without a handle and combine parallel siblings and pure result rows.
An empty projected result still gets the existing non-text marker.

Text recognition is a heuristic based on known harness wrappers. Fenced examples
and untagged user text are preserved; unfenced user text imitating those wrappers
can match. Both thresholds accept 0 to disable their text class. If state fitting
removes a candidate's preview, it stays unscored. The optional target excludes the
system/tool prefix; judge total depth using the next request's actual usage.

## Scope and caveat

Function hooks are early access and may change between Claude Code releases.
Without the `session.compact` event no supported API installs replacement rows;
the usage hook logs that incompatibility and requests no built-in summary.
This mod uses the generated declarations from 2.1.274 in
`types/claude-code.d.ts`; regenerate and review that file after a
Claude Code upgrade.
